```

│                    CLOCK IN EVALUATION RUBRIC (100%)                   │

│  - Unlocks what desktop can't do   │  - Reproducible testing steps     │
└────────────────────────────────────┴───────────────────────────────────┘
```

1. **Stickiness & Product-Market Fit (25%):**  
   Does this app become part of the user's daily mobile routine? Does it have genuine retention, network effects, or utility for Seeker holders?
2. **Mobile User Experience (25%):**  
   Is it fast, responsive, and tactile? Does it feel like a polished consumer product rather than a janky web port? (Native animations, biometric integration, haptics, clear feedback).
3. **Innovation & X-Factor (25%):**  
   Does it demonstrate unique technical capability that only a dedicated crypto smartphone can deliver? (Hardware enclaves, passkeys, AI agent delegation, out-of-band quorum).
4. **Presentation & Demo (25%):**  
   Is the submission crystal clear? Can judges install and test the APK in under 2 minutes without hitting fatal crashes or complex setup roadblocks?

## 4. 🚨 Rules & Eligibility Constraints

> [!IMPORTANT]
> **NO WEB-WRAPPERS ALLOWED:** The hackathon explicitly states: *"Submissions that simply wrap existing websites into Android applications will not be accepted."* Your app must be a functional, native Android application with mobile-specific primitives.

- **Mobile-First Android App:** Submissions must provide a working, release-ready Android APK (`.apk`).
- **Solana Mobile Stack (SMS) & Seeker Target:** Must interface with Solana Mobile architecture (Mobile Wallet Adapter, hardware biometrics, Seeker hardware security, or dApp store specifications).
- **Freshness Window:** Projects must have been started no earlier than **June 8, 2026** (3 months prior to launch date), or demonstrate substantial, net-new mobile development completed during the September 8 – October 8 hackathon period.
- **Open Source Source Code:** Link to a public GitHub repository containing the full codebase.
- **Reproducibility:** Clear `README.md` with instructions on how to run locally and how judges can verify the on-chain transactions on Devnet or Mainnet.

When submitting through [solanamobile.radiant.nexus](https://solanamobile.radiant.nexus), you must submit:

5. **Contract Receipts & Verification:** Program IDs, verified IDLs, and transaction signatures on Solana Explorer.
