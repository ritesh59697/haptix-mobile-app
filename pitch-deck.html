The problem02

The backup is paper. The prompt is the same for every amount.

01

Twelve words

Lose the page and the account is gone. Someone else finds it and the account is gone.

02

One tap

A 0.05 SOL swap and a large transfer ask for the same fingerprint. After enough taps, people stop reading.

03

The agent

A bot either holds a raw key, or it stops and waits for you. There is no ceiling in between.

The product03

The amount picks the signer.

0.1 SOL or under

The phone signs.

One passkey. Solana's secp256r1 precompile checks the signature. The private key never leaves the device.

Over 0.1 SOL

The Mac signs too.

The phone approves, then the paired Mac approves with Touch ID. The two keys never meet.

On-chain04

The program enforces it. The app does not.

Signature

Passkey

The program reads the secp256r1 instruction from the sysvar and checks it. It does not trust a result the app reports.

Agents

Ceiling

A session key can spend up to a set amount, until it expires. Past either bound, the transaction fails.

Lost phone

24 hours

Panic freeze stops outflows. Replacing the passkey waits out a timelock. The guardian cannot skip it.

Check it yourself.

Default limit

0.1 SOL

Stored on the wallet account. Changing it needs both devices. The devnet test raises it to 0.5, then lowers it to 0.05.

Recovery

24h timelock

A guardian can start recovery. The wallet freezes until the window ends, or until both passkeys cancel it.

Seeker test mint

50 SKR

The same rule, on a test mint. Over 50 SKR needs both devices. This is not a mainnet airdrop.
